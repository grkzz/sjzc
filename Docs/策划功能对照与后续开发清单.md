# 策划功能对照与后续开发清单

核对日期：2026-11-06。

主要依据为《2026.10.21、孵蛋及卡组构成思路第二版》《游戏战斗规则及流程》、A001/A005 卡组文档和《游戏定价，内容量等基础信息》，并直接对照当前 BattleModel、PrototypeGame、卡牌配置及预设体工具。8 月旧版和此前开发大纲仅作背景；大纲中的建议不等于已经确认的正式需求。

## 当前完成程度

当前是**可以完整打完一局的单机战斗原型**，已有放蛋、手动孵化、随机结果、性别、相邻繁殖、阶级与代数、攻击反击、部分蕴灵效果、AI、简化霸主、结算重开、金币与胜场记录。竖屏透视棋盘和卡牌外观编辑工具已完成基础版本。

当前配置为 11 种普通怪兽、1 种霸主、5 种原始蛋、5 种道具。两方是固定 30 张教学牌组，使用相同蛋卡与道具集合，尚未形成两套完整且各有特色的正式牌组。

## 优先级一：补齐核心规则和玩家决策

| 功能 | 当前实现 | 尚缺内容 |
| --- | --- | --- |
| 繁殖后的选择 | 按配对快照计算，依次放入首个空蛋位；满格跳过 | 展示候选蛋，让玩家选保留、销毁和放置位置；满格时处理替换/放弃，按最终规则确定 |
| 同性重抽 | 全场同性时自动随机选一只、重抽一次 | 玩家选择想重抽的怪兽、倒计时及跳过；原稿写 20 秒，多选和次数限制需收敛 |
| 蛋池演化 | 从父方已知池削减非核心，维持末位隐藏 5% | 纯血队双核心概率、最终核心选择、跨属性与跨种族杂交、母方属性及父母效果继承；代数不应仅为原型的固定上限 |
| 孵化表现 | 直接按权重得出结果，日志记录随机值，详情展示概率 | 轮盘动画、隐藏结果反馈；动画只表现已生成的逻辑结果 |
| 蛋的种类 | 原始配置全部为 1 回合、一阶；繁殖可生成二、三阶 | 可直接构筑的二、三阶蛋、0 回合蛋内容、坏蛋空池、特殊定向单怪池；当前配置校验仅允许 2–5 项池 |
| 蛋的防御 | 自动选第一枚合资格蛋拦截一次并回退计时 | 第二次受击销毁未实现；主动攻击蛋、是否由防守方选蛋需先统一规则 |
| 正式开局 | 玩家固定先手，教学起手固定 3 蛋 2 道具 | 随机先后手、随机起手；教学预设可以单独保留。换牌是否存在需另定 |
| 决斗者技能与计时 | 有怪兽主动技能按钮 | 角色特殊技能、原稿的 180 秒行动倒计时及超时处理 |

现有 Breed 只是原型算法，不能视为完整继承系统。原始蛋的 Tier 当前默认一阶；补高阶原始蛋时，需要按基础孵化时间正确初始化，不能只增加 JSON 条目。

## 优先级二：还原卡组和任务

任务现简化为“孵化 5 只召唤最强毁灭机器人”。原案要求任务卡构筑、开场选择、仅在场累计、替换清零、最多携带 3 张且同名最多 2 张，以及完成后继续放置下一任务。现阶段均未形成正式系统。

最强毁灭机器人已有登场弃手牌、蕴灵光环，未做回合结束召唤三阶怪兽。A005 的另外两个任务与霸主未接入；霸主在当前数值结构中复用三阶模板并标记 IsBoss，也未建立独立四阶数据表示。

已有卡牌也包含以下差异，不能按“卡牌名称存在”视为效果全部完成：

| 卡牌 | 当前与原稿的差异 |
| --- | --- |
| 特殊工艺 | 当前直接给怪兽 +3/+3；原稿给蛋附加孵化后增益 |
| 绝望抽卡 | 当前立即抽 1；原稿下一次抽牌多抽 1 |
| 折纸工艺 | 当前令蛋就绪，仍需玩家操作孵化；原稿“提前孵化”的具体流程需定稿 |
| 三角积木蛇 | 当前单目标伤害并消耗 1 自身蕴灵；原稿按蕴灵数影响目标数量，未写相同消耗 |
| 司南鳌 | 当前只加速一次；原稿按蕴灵数重复触发 |
| 咬咬咬人鳄 | 当前概率摧毁攻击者；原稿可破坏对方怪兽或蛋，目标规则待细化 |
| 超频电气灶 | 当前有自身蕴灵即可追加攻击；原稿还涉及同系友军条件 |
| 老式打火机鹳 | 当前只有基础数值，未实现登场消耗蕴灵以解除蛋防御 |

其余未接入效果包括退阶续命、强制回蛋、部分复制道具、无伤、死亡铺蛋、攻击次数转移、临时过牌回收、负荷/眩晕等。A002、A004、A006 等其他种族体系未实现；A003 本身内容仍较少，需先补设计。

建议先完成 A001 与 A005 两套小规模正式牌组，把效果时点、目标、持续时间、死亡处理顺序整理成可执行规则，再扩大卡池。

## 优先级三：从单局原型变成试玩游戏

| 模块 | 当前状态 | 应补内容 |
| --- | --- | --- |
| 图鉴与构筑 | 无正式界面，固定牌组在代码内生成 | 已拥有/已见卡牌、卡牌检索、蛋池查看、多卡组保存和切换 |
| 构筑校验 | 有基础数据校验，没有完整牌组规则 | 30–40 张、种族和属性暂定各 15 点、同核心蛋/同名道具限制、任务限制、额外怪兽库关联 |
| 训练场 | 一个固定 AI 对手 | 多个预设牌组和难度；AI 决策考虑站位、配对、保留蕴灵与任务 |
| 教学与剧情 | 开场文字弹窗、规则说明 | 分步骤引导、角色立绘与对话、剧情标记、胜败对白、战败报幕、可重试关卡 |
| 地图与进度 | 直接进入战斗 | 学院/遗迹/比赛等节点、解锁条件、关卡奖励、战后返回流程 |
| 收集与奖励 | 金币和胜场以 PlayerPrefs 保存 | 卡牌奖励、抽卡机、图鉴成就、收藏和卡组、章节与设置的正式存档及版本迁移 |
| 局外合成 | 未实现 | 五张符合条件的怪兽合成蛋，配方和产出规则先定稿 |
| 声音与动作 | 以静态界面和文本反馈为主 | 放牌、攻击、受击、死亡、孵化、产蛋、霸主登场的动画和音效 |
| 手机端 | 竖屏布局和基础触控 | Android/iOS 构建、真机安全区域、触控尺寸、长文本、性能、内存与发热验证 |
| PC 发行 | 可构建本地 Windows 试玩 | 正式主菜单、设置、分辨率/音量等操作，以及所选发行平台的相关接入 |

## 卡牌工具仍可完善的部分

当前编辑器负责外观，已支持创建、加载、图片文字图层、拖动和缩放、保存/另存、撤销及 PNG 导出。

还没有统一的卡牌规则编辑器；卡名、攻击、生命、效果文本与 BattleModel/JSON 不自动同步。当前完整参考 PNG 的印刷文字无法作为图层修改，正式阶段需要分层卡框、插画和图标，并从同一份定义自动填充卡面。卡牌详情弹窗的大图仍使用原始参考图片，未统一为编辑后的 prefab。

后续可增加种族/属性图标插槽、各类卡牌模板、图层锁定、对齐参考线、批量生成、资源引用与溢出检查。优先做数据绑定和模板，批量操作按美术实际使用量追加。

## 需要定稿的策划问题

这些属于原案未统一，不能直接当成程序遗漏：

- 玩家生命 50 / 60：当前暂用 60。
- 任务还是独立场地：旧战斗文档与第二版称呼及流程不同。
- 蕴灵任务的“10 次”：统计点数、次数、获得还是消耗。
- 双核心最终保留第一位、较高概率核心，还是玩家选择。
- 满蛋位直接停止产蛋，还是先生成后供玩家选择。
- 孵化自然递减时点、回合结束效果与繁殖的顺序。
- 牌库耗尽、手牌上限、平局和普通三阶繁殖封顶：目前有原型处理，需正式确认。
- 属性/种族 15 点是暂定值；全部正式规则尚未做平衡验证。

## 建议实施顺序

1. 定稿一页战斗规则，并把现有简化项标清楚。
2. 补繁殖交互：选蛋、选位、放弃、同性重抽，再补轮盘。
3. 完成 A001/A005 的入选卡牌效果和正式任务。
4. 统一卡牌数据与外观，完成图鉴及牌组编辑、校验。
5. 加 2–3 场教学和一小段学院/遗迹剧情，接入奖励与正式存档。
6. 做音画反馈、PC 试玩打包和手机真机测试，再逐步扩种族与章节。

PVP 房间、牧场挂机、卖卡交易、卡牌店经营在资料中属于其他玩法或设想；应作为后续扩展单独评估，不阻塞首个 PVE 试玩。原稿还描述了约 8 小时全收集与多个赛事阶段，但关卡与可执行剧情需要继续制作，当前不能按已有设定文本视为完成内容。
