# 二维背景与三维棋盘

新版把棋盘1作为真实矩形网格的 UV 贴图，通过透视摄像机渲染，再与棋盘2的竞技场前景合成。棋盘和场上卡牌均处于同一个三维空间，前景中的墙壁遮挡棋盘边缘。手牌、生命、任务和操作按钮保留在屏幕空间。

## 运行

- 场景仍为 `Assets/_Game/Scenes/PrototypeBattle.unity`，进入 Play 后生成透视棋盘。
- 新的 Windows 试玩：`Builds/PerspectiveWindows/ShenYiPerspective.exe`。
- 旧版平面试玩保留在 `Builds/Windows`，避免覆盖已有可运行版本。当前源码使用新版透视表现。
- 默认 540×960，宽屏时保留 9:16 画幅。

## 结构

- `PerspectiveBoardWorld`：独立三维场景根节点，避免嵌套屏幕 Canvas 改变三维变换。
- `BoardTexturedMesh`：矩形网格、完整 UV 与 MeshCollider，贴棋盘1。
- `BoardThickness`：棋盘厚度，位于表面后方，与贴图保持间隔避免深度冲突。
- `CardsOnBoard`：世界空间 Canvas，卡牌与卡位随摄像机产生近大远小。
- `BoardPerspectiveCamera`：透视相机，使用独立图层，只渲染棋盘和卡牌。
- `PortraitPerspectiveBoard`：1080×1920 渲染纹理，供二维界面合成显示。
- `ArenaForeground`：棋盘2前景，透明中心露出三维棋盘。

点击经过屏幕坐标 → 渲染画幅坐标 → 摄像机射线 → 棋盘 MeshCollider UV → 实际格位，使用现有战斗指令执行操作。自动试玩也走这一射线路径检查放蛋和孵化。

## 素材处理

原始素材保留。新增 `ArenaForeground.png` 为棋盘2的派生前景，清除了透明开口里残留的黄绿色碎片；棋盘1仍完整贴在模型上。没有把整个竞技场重建成三维模型。

本阶段使用 Unity 生成基础棋盘，没有使用 Blender。后续如需要倒角、独立边框、装饰或更复杂的桌体，可将 `BoardTexturedMesh` / `BoardThickness` 替换为 Blender 导出的模型，保持 UV 方向和卡位坐标一致。

## 后续调整入口

`Assets/_Game/Scripts/UI/PerspectiveBoard.cs` 的 `Initialize` 中定义：

- 棋盘世界尺寸及源图比例。
- 远边与近边的目标屏幕位置，控制与背景开口的匹配。
- 摄像机视野和倾斜、投影中心偏移。
- 棋盘厚度和卡牌离地高度。

卡牌现直接使用「孵蛋演示文件/1.1 蛋卡表面描述」中的完整 PNG 卡面，以原始 3:4 比例放到棋盘上，保留卡框、插画和底部说明区。动态攻击/生命/性别和孵化状态移至卡外的小状态条，详细数据通过弹窗查看。手牌中的蛋卡也使用完整卡面，选中时用外轮廓高亮。素材名称与数值仍属于模拟卡面，以对局状态与详情中的实际数据为准。

导入素材位于 `Assets/_Game/Resources/Prototype/CardFaces`，`SourceMapping.json` 记录对应原始路径。怪兽按单属性、双属性及草属性选择示例卡面，不假设这些图片已经对应所有实际卡牌。远端卡牌天然更小，可通过详情弹窗阅读完整效果；手机真机的点击舒适度需后续实测。

## 验证

Windows 构建成功，0 错误、0 警告。透视摄像机验证近处/远处等宽物体的投影尺寸比约为 1.456；自动试玩通过 9 次摄像机射线格位点击完成放蛋与孵化，随后完成 21 个双方回合计数的整场对战。运行截图为 `Logs/PerspectivePortrait.png`，结算截图为同名 `.result.png`，结果与日志分别为 `.json` 和 `Logs/PerspectivePlayer.log`。
